## Objective

Make the `Department` type actually hold the things a department contains, so
that `SpreadsheetLayout.tsx` can stop using `any` to get around the type system.

## Background

The org tree we agreed on in the W33 notes is:

```
Organization → OperationsSector → Department → Cluster → Team
```

with one wrinkle: **teams can sit directly under a department, or under a
cluster inside a department.** The Development department uses clusters
(Caribbean, Bering, …) which contain teams (Whale, Lemon, …). The Finance
department has teams (Accounting, Investment) with no cluster in between.

Right now `Department` in `utils/model/types.ts` is:

```ts
export interface Department {
  name: string;
  abbreviation?: string;
  members: Membership[];
}
```

No teams. No clusters. So `DepartmentLayout` in `SpreadsheetLayout.tsx` was
written as `department: Department | any` and then does
`department.teams.map(...)` — which compiles only because `any` switches off
type checking. The same escape hatch is in `OperationsSectorLayout`. That `any`
is hiding real bugs from us, and it will keep hiding them as the file grows.

## Files you will touch

- `utils/model/types.ts`
- `src/components/SpreadsheetLayout.tsx`
- `src/pages/members.tsx` (only as far as needed to keep the build passing)

## What to change

1. Add `teams` and `clusters` to `Department`. Both should be arrays. Decide —
   and write a one-line comment explaining your decision — whether they are
   required-but-possibly-empty (`teams: Team[]`) or optional (`teams?: Team[]`).
   Argue it from how the consuming code reads: which choice means
   `DepartmentLayout` needs fewer `?.` and `??` guards?
2. Remove `| any` from the `department` prop of `DepartmentLayout` and from the
   `sector` prop of `OperationsSectorLayout`.
3. Fix whatever breaks. Some of it will be genuine bugs that `any` was hiding.
   Expect at least:
   - `DepartmentLayout` renders `department.teams` but ignores
     `department.clusters`. For this spec, render the department's direct teams
     and **leave a `TODO(W38.1.2)` comment** where cluster rendering will go.
     Do not build cluster rendering here.
   - `members.tsx` builds a `Department` with an object literal and an
     `as Department` cast. Casts lie to the compiler the same way `any` does.
     Remove the `as` cast and let the object literal be checked properly.
4. While you are in `TeamLayout`: the `.map()` over `team.members` returns a
   `<div>` with no `key` prop. React needs one. Fix it. Use something stable —
   a member's primary email is unique, the array index is not (the whole point
   of W38.3 is that these lists get reordered).

## How to approach it

- Make the type change first, then run `npm run build` and let TypeScript hand
  you the list of things to fix. Work the list top to bottom.
- Do not "fix" an error by adding `any`, `as`, or `!`. Those are what got us
  here. If you are genuinely stuck on one, leave it, and bring it to the group
  chat with the error text.
- `Team` and `Cluster` are already defined in `types.ts` above `Department` —
  read them before you start so you know what you are putting in the arrays.

## Acceptance criteria

- [ ] `Department` has both a teams array and a clusters array, with a comment
      explaining the required-vs-optional decision.
- [ ] Neither `DepartmentLayout` nor `OperationsSectorLayout` uses `any`.
- [ ] No `as Department` / `as OperationsSector` casts remain in `members.tsx`.
- [ ] Every element produced by a `.map()` in `SpreadsheetLayout.tsx` has a
      `key`, and no key is the array index.
- [ ] `npm run build` passes with zero TypeScript errors.
- [ ] `npm run dev` renders the members page without a blank screen or a red
      console error.
