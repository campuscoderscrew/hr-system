## Objective

Make a member's column in the spreadsheet pick up and drag. Nothing accepts the
drop yet — that is W38.3.3. This spec ends when you can drag a member around the
screen and see a sensible drag preview.

## Background

We are using the **native HTML5 drag-and-drop API**, not a library. Reasons: no
new dependency, it is what the platform gives us, and it is a genuinely useful
thing to have learned. It is also famously quirky, which is why this is its own
one-hour spec.

The three things that surprise everyone:

- An element only drags if it has the `draggable` attribute. There is no
  "drag mode".
- Data is passed through a `DataTransfer` object, and **it can only carry
  strings.** You cannot put a `Membership` object on it. You put an identifier on
  it and look the member up on drop.
- The data you set in `dragstart` is not readable during `dragover` in most
  browsers — only in `drop`. So `dragover` cannot make decisions based on *who*
  is being dragged unless you also keep that in React state. Plan for it.

## Files you will touch

- `src/components/SpreadsheetLayout.tsx`

## What to change

1. In `TeamLayout`, add `draggable` to each member's column `<div>`.

2. Handle `onDragStart`. Put enough on the event's `dataTransfer` for a drop
   handler to identify exactly which position of which member is moving. That is
   at minimum the member's primary email plus the source team — the same member
   can appear in two teams, and dropping "Alex" somewhere is ambiguous unless you
   say which Alex-row was grabbed.

   Serialise it as JSON into a custom MIME type, e.g.
   `event.dataTransfer.setData("application/x-ccc-member", JSON.stringify({...}))`.
   Also set a plain `text/plain` fallback with the member's name — it costs one
   line and makes dragging into a text field do something harmless instead of
   nothing.

3. Set `event.dataTransfer.effectAllowed = "move"` so the cursor shows a move
   affordance rather than a copy one.

4. Give the dragged element a visual state while it is in flight — reduced
   opacity is the convention. Track it with `onDragStart` / `onDragEnd`. `onDragEnd`
   fires whether the drop succeeded or was cancelled, so it is the right place to
   clear the state. **If you only clear on drop, a cancelled drag leaves the
   member greyed out forever.**

5. Make the drag *affordance* visible before the drag starts: `cursor-grab` on
   the cell, `cursor-grabbing` while dragging. Users should be able to tell that
   a thing is draggable by looking at it.

6. Do not make the entire team card draggable, and do not make individual
   `<span>`s draggable. The unit being dragged is one member's column.

## How to approach it

- Get `draggable` + a `console.log` in `onDragStart` working first. If that log
  never fires, nothing else you write matters.
- Text selection inside the cell will fight the drag. `user-select: none` on the
  draggable element (`select-none` in Tailwind) usually resolves it. Note the
  tension with W38.2.4, which wants the *hover card* text selectable — that is
  fine, they are different elements.
- Hover and drag on the same element will interact. If the hover card pops up
  mid-drag it will be distracting. You are allowed to suppress the card while a
  drag is in progress; coordinate with whoever has W38.2.3 rather than both
  editing the same handler blind.

## Acceptance criteria

- [ ] A member's column can be picked up and dragged with the mouse.
- [ ] `dragstart` sets a custom-MIME-type payload identifying the member and the
      source team, plus a `text/plain` fallback.
- [ ] The cursor shows a move (not copy) affordance during the drag.
- [ ] The dragged cell is visually distinct while in flight.
- [ ] Pressing `Escape` mid-drag, or dropping on nothing, restores the cell to
      normal appearance — no permanently greyed-out members.
- [ ] `cursor-grab` / `cursor-grabbing` are applied.
- [ ] Only member columns are draggable; team and department containers are not.
- [ ] `npm run build` passes.
- [ ] Your PR includes a short screen recording of a drag.

## Out of scope

- Anything accepting the drop — W38.3.3.
- Calling `moveMemberToTeam` — W38.3.3.
- Keyboard-accessible reordering. Native HTML5 DnD is mouse-only; a keyboard
  alternative is logged in `features_TODO.md`.
