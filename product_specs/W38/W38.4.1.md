## Objective

Build the confirmation dialog the business spec requires, as a standalone
reusable component that knows nothing about members.

## Background

Straight from the spec:

> Member data cannot be deleted without typing out a "DELETE" verification

This is the GitHub "type the repository name to confirm" pattern. It exists
because an `OK / Cancel` dialog is dismissed reflexively — people click through
it without reading. Making someone type a specific word forces them to stop.

Build it generic. We will want the same dialog for deleting a team and for
removing a role later, so it should take the confirmation word and the message as
props rather than hardcoding member language.

## Files you will touch

- `src/components/ConfirmDeleteModal.tsx` (new file)
- `src/pages/members.tsx` (temporary scaffolding only — removed before PR)

## What to change

1. Create `src/components/ConfirmDeleteModal.tsx`. Suggested props:

   ```ts
   {
     open: boolean;
     title: string;
     description: React.ReactNode;   // so callers can pass formatted content
     confirmWord?: string;           // default "DELETE"
     onConfirm: () => void;
     onCancel: () => void;
   }
   ```

   The component owns the typed-input state. It does **not** own `open` — the
   caller does. Renders nothing when `open` is false.

2. The confirm button is disabled until the typed text matches `confirmWord`
   **exactly**: case-sensitive, and trimmed of surrounding whitespace only. Show
   the required word in the label so the user knows what to type, e.g.
   *Type `DELETE` to confirm*.

3. A backdrop behind the dialog. Clicking the backdrop cancels. `Escape` cancels.
   Both should reset the typed text, so re-opening the dialog never starts with
   `DELETE` already in the box — that would defeat the entire point.

4. Focus the text input when the dialog opens. A dialog that requires typing and
   does not focus its input makes every user click twice.

5. Make the destructive action look destructive: red confirm button, neutral
   cancel. Cancel should be the easier target.

6. Consider whether the native `<dialog>` element is a better fit than a `<div>`
   with a backdrop — it gives you `Escape` handling, focus trapping and the
   backdrop for free, at the cost of a slightly unusual API (`showModal()`, and
   styling via `::backdrop`). Try it. Write two sentences in your PR on what you
   found. Either implementation is acceptable.

## How to approach it

- Develop it visible: temporarily render it with `open={true}` in `members.tsx`
  and `onConfirm={() => console.log("confirmed")}`. Delete the scaffolding before
  you push.
- Match the existing app styling — rounded corners, `shadow-xl`, white surface.
  `src/pages/login.tsx` has the closest existing card styling; reuse its
  vocabulary.
- Use the `cn()` helper from `src/utils.tsx` for conditional classes.

## Acceptance criteria

- [ ] `src/components/ConfirmDeleteModal.tsx` exists and takes the confirmation
      word as a prop with a `"DELETE"` default.
- [ ] The confirm button is disabled until the exact word is typed;
      `delete`, `Delete` and `DELETE ME` do not enable it.
- [ ] Clicking the backdrop, pressing `Escape`, and clicking Cancel all cancel.
- [ ] After cancelling and reopening, the input is empty and confirm is disabled
      again.
- [ ] The input is focused when the dialog opens.
- [ ] The component renders nothing when `open` is false.
- [ ] It contains no member-specific logic — it could be used to delete a team
      tomorrow with no changes.
- [ ] No temporary scaffolding remains in `members.tsx`.
- [ ] Your PR states what you found with `<dialog>`.
- [ ] `npm run build` passes.
