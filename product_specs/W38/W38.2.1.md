## Objective

Write the pure functions the hover card will need, before any UI exists. Given a
member, produce their role timeline in the order and format the business spec
asks for.

## Background

From the business spec, hovering a member should show:

> Previous roles in CCC, including a timeline of those roles
> e.g. `Developer (August 5th, 2024 - November 1, 2025) → Primary Lead (November 1st, 2025 - December 20th, 2025)`
>
> Current other roles in CCC (since some members have multiple positions)

Everything needed is already on `Membership.positionHistory: Position[]`. A
`Position` has `role`, optional `experienceLevel`, `startDate`, and an
**optional `endDate` — absent means the position is currently held.** There is
already a `currentPositions(member)` helper in `types.ts` that filters on
exactly that. Read it before you write anything.

There is also a `formatRole(role, level)` helper that handles the
Associate/Intermediate/Senior prefix rules (`Associate` → `Assoc.`,
`Intermediate` → nothing, `Senior` → `Sr.`). Use it. Do not re-implement it.

This is deliberately a **no-React** spec. Doing the data work first means the
component in W38.2.2 is almost entirely markup.

## Files you will touch

- `utils/model/positions.ts` (new file)

## What to change

Create `utils/model/positions.ts` and export these four functions. Signatures are
given; the bodies are yours.

1. `pastPositions(member: Membership): Position[]`
   Positions that have ended (they have an `endDate`), sorted **oldest first** so
   the timeline reads left to right.

2. `otherCurrentPositions(member: Membership, excluding?: Position): Position[]`
   The member's current positions, minus the one the caller is already showing.
   Used for the "current other roles" section — when you hover John on Team
   Whale, the card should list his Treasurer role, not repeat "Developer, Team
   Whale" back at you.

3. `formatPositionPeriod(position: Position): string`
   `"August 5, 2024 – November 1, 2025"` for a closed position, and something
   that reads correctly for one still held — `"August 5, 2024 – Present"`. Use
   `Intl.DateTimeFormat` or `toLocaleDateString`; do not hand-roll a month-name
   array.

4. `roleTimeline(member: Membership): { label: string; period: string; isCurrent: boolean }[]`
   The full timeline, oldest first, ending with the currently-held positions.
   `label` should use `formatRole` so experience level is applied.

## How to approach it

- `positionHistory` is not guaranteed sorted. Sort it yourself. `Date` objects
  compare correctly with `-` (`a.startDate.getTime() - b.startDate.getTime()`).
- Decide what happens when two positions start on the same day, and write a
  comment saying what you chose. Any consistent answer is fine; an unstable sort
  that reorders on every render is not.
- `data.ts` has members with genuinely awkward shapes — some with an empty
  `positionHistory`, some with a single `{ role: "M", startDate }` and nothing
  else. Open it and find them. Your functions must return sensible empty results
  for those, not throw.
- None of these functions may import from `src/`. They are model code and will
  move to the backend in Phase 2.

## Acceptance criteria

- [ ] `utils/model/positions.ts` exists and exports all four functions with the
      signatures above.
- [ ] No function mutates its argument (sorting a copy, not the original array).
- [ ] A member with an empty `positionHistory` returns `[]` / `""` rather than
      throwing.
- [ ] A member with exactly one current position returns `[]` from
      `otherCurrentPositions` when that position is passed as `excluding`.
- [ ] `formatPositionPeriod` renders a currently-held position without printing
      `undefined` or `Invalid Date`.
- [ ] `formatRole` is used for labels rather than re-implemented.
- [ ] `npm run build` passes.
