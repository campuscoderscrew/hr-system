## Objective

A bar above the spreadsheet with a search box and a few filters. The org tree
shows only matching members, and drag and delete keep working correctly while
filtered.

## Background

`members.tsx` holds `appMembers` in state and builds `orgTree` from it with
`buildOrganization`. Filtering belongs **between** those two steps:

```
appMembers (full) ──► filterMembers ──► buildOrganization ──► render
      ▲                                                          │
      └────────── onMembersChange / delete (full list) ◄─────────┘
```

**The trap:** the drag-and-drop handler in `TeamLayout` takes the `members`
prop, applies the move to a copy, and hands the whole copy to
`onMembersChange`. If you pass the **filtered** list down as `members`, the
first drag while filtered replaces state with only the visible members, and
everyone else is silently deleted. The full list goes down as `members`. Only
the tree is built from the filtered list.

## Files you will touch

- `src/components/MemberFilterBar.tsx` (new)
- `src/pages/members.tsx`

## What to change

1. Build `MemberFilterBar` as a controlled component: it receives the current
   `MemberFilter` and an `onChange`, and holds no filter state of its own.
2. Controls:
   - a text search box,
   - a role multi-select,
   - an availability-status multi-select,
   - a "minimum front-end / back-end proficiency" control,
   - a **Clear filters** button (only shown when something is set).
3. In `members.tsx`, hold the filter in state and derive
   `filtered = filterMembers(appMembers, filter)` with `useMemo`. Build the tree
   from `filtered` and pass the **full** `appMembers` down for mutations.
4. Show "Showing N of M members". When nothing matches, show an empty state
   with a Clear button, not a blank page.

## How to approach it

- Write the trap down as a test before building UI: filter to one person, drag
  them, clear the filter, and count members. The count must not drop.
- Typing in the search box rebuilds the tree on every keystroke. With ~150
  members that is probably fine. Measure before adding debouncing, and say what
  you found in the PR.
- Use native `<label>`s for every control. A search box without a label is
  invisible to a screen reader.
- If Kevin's W45.2.3 has landed, guests cannot see emails, so the search should
  not match on emails for them either. Ask Kevin how `can()` is exposed.
