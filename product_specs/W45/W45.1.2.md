## Objective

In development, a `fetch("/api/...")` made from the React app reaches Express.
One command starts both servers.

## Background

Vite serves the frontend on port 5173. Express listens on port 3000. Today the
drag-and-drop code already calls `fetch("/members/.../move-team")`, and that
request goes to **Vite**, which returns 404. The failure is silent apart from an
`alert()`.

There are two ways to fix this:

- **CORS**: the browser calls `http://localhost:3000` directly, and Express
  sends headers allowing it. This works, but session cookies (which W45.2 and
  `requireAuth` depend on) then need `credentials: "include"` on every fetch,
  plus a matching `cors({ origin, credentials: true })`. It is easy to get
  subtly wrong.
- **Proxy**: Vite forwards `/api/*` to port 3000. The browser sees one origin,
  cookies just work, and production can do the same thing behind one host.

We are doing the proxy. This is also why W45.3.1 moves every route under
`/api`. `/members` is both a **page** and an **API route**, so proxying it
would send a browser navigating to the members page off to Express, and it would
get raw JSON back.

## Files you will touch

- `vite.config.ts`

## What to change

1. Add a `server.proxy` entry to `vite.config.ts` that forwards `/api` to
   `http://localhost:3000`. Read Vite's docs on `server.proxy`, including
   `changeOrigin`, and decide whether we need it.
2. Add a script that starts Vite and the Express server together and stops both
   on Ctrl+C. Pick a small, well-maintained tool for this (`concurrently` is
   common) and justify the choice in your PR. Keep `dev` and `server` working
   on their own.
3. Make the two outputs readable: prefix or colour each process's logs so a
   server error is obviously a server error.
4. While you are in `vite.config.ts`, delete the commented-out old config at
   the bottom.
5. Update the README's run instructions.

## How to approach it

- Prove the proxy works before touching the app: start both servers and open
  `http://localhost:5173/api/members` in the browser. JSON means it works. The
  React app means the proxy did not match.
- Then open `http://localhost:5173/members`. You should get the **page**, not
  JSON. If you get JSON, the route split is wrong.
- `npm run server` uses `tsx` but does not watch. Ask yourself whether the
  combined script should restart the server on file changes (`tsx watch`), and
  note your decision in the PR.
