## Objective

`src/pages/members.tsx` no longer imports `data.ts`. It fetches members from
the server through one small API module and shows sensible loading and error
states.

## Background

This is the visible step of "move model ownership to the server". After this
spec, the frontend no longer owns the data for **reads**. Writes (drag, delete)
still mutate local state, and they move to the API next week. Keeping reads and
writes in separate weeks keeps each PR reviewable.

## Files you will touch

- `src/api/members.ts` (new)
- `src/pages/members.tsx`

## What to change

1. Create `src/api/members.ts`. Components never call `fetch` directly. They
   call functions from here. Start with:
   - `getMembers(): Promise<Membership[]>`, which calls `GET /api/members`,
     checks `response.ok`, and runs the body through `reviveMembers` from
     W45.1.1.
   - Move the existing `handleMoveTeamAPI` body out of `members.tsx` into a
     `moveMemberToTeam(...)` function here, pointed at `/api/...`.
2. On a non-2xx response, throw an `Error` whose message comes from the
   server's `{ error }` body. The server always sends that shape since PR #10.
   Fall back to the status text if the body is not JSON.
3. In `members.tsx`, initialise `appMembers` as empty and load it in an effect.
   Track three states: loading, error, loaded.
4. Render a loading state and an error state. The error state shows the message
   and a **Retry** button. "Server not running" is the error every new member
   hits first, so make it obvious what to do.
5. Remove the `data.ts` import from `members.tsx`.

## How to approach it

- React 18 Strict Mode runs effects twice in development. Make sure that does
  not cause a double render bug or a state update after unmount. Look up the
  "ignore stale response" pattern for fetching in `useEffect`.
- Stop the server and reload the page. Is the error message something a club
  member would understand?
- `grep -r "model/data" src/` afterwards. `login.tsx` may still import it
  (that is W45.2's business). `members.tsx` must not.

## Acceptance criteria

- [ ] `members.tsx` does not import `utils/model/data`.
- [ ] Members render from `/api/members` with the server running.
- [ ] With the server stopped, the page shows an error and a working Retry
      button. It does not show a blank screen or a crash.
- [ ] A loading state is visible on slow networks (test with DevTools
      throttling).
- [ ] The delete modal's tenure text works, which proves dates were revived.
- [ ] No component calls `fetch` directly.
- [ ] `npm run build` passes.

## Out of scope

- Sending drag/delete/edit through the API and reconciling with the server
  response. This is next week; add it to `features_TODO.md`.
- Caching or a data-fetching library.
- Auth headers. The proxy makes session cookies same-origin.
