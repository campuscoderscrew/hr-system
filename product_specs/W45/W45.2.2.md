## Objective

The navbar shows who is logged in, with their user type, and has a working
**Log out** control. Logged out, it shows **Log in**.

## Background

`src/components/navbar.tsx` is a "CCC" label plus one hardcoded `Login` link.
Once W45.2.1 lands, the app knows who is logged in, so the navbar should show
it. It is also the natural home for logging out, which currently is not
possible.

## Files you will touch

- `src/components/navbar.tsx`

## What to change

1. Read the current user from `UserAuthContext`.
2. Logged out: show the existing **Log in** link.
3. Logged in: show the username and a small user-type badge (`ADMIN`, `HR`,
   `MEMBER`, `GUEST`), a **Members** link, and a **Log out** button.
4. **Log out** calls the context's `logout()` and navigates to `/login`.
5. Make the "CCC" label a link to `/members` when logged in and to `/login`
   when logged out.

## How to approach it

- Log out is an action, not a navigation, so it should be a `<button>`, not a
  `<Link>`. Screen readers announce them differently.
- Keep the badge colours readable. Maya is defining colour tokens in W45.6.1.
  If they have landed, use them. If not, use neutral Tailwind colours and leave
  a `// TODO W45.6` comment.
- Check the narrow layout: the navbar should not overflow at 375px.

## Acceptance criteria

- [ ] Logged out: only **Log in** is shown.
- [ ] Logged in: username, user-type badge, **Members** and **Log out** are
      shown.
- [ ] **Log out** clears the user (including anything W45.2.1 put in
      `sessionStorage`) and lands on `/login`. **Back** does not get you into
      `/members`.
- [ ] Log out is a `<button>` and is reachable with Tab and Enter.
- [ ] No horizontal overflow at 375px wide.
- [ ] `npm run build` passes.

## Out of scope

- Calling `POST /api/logout` on the server (follows the server-login TODO from
  W45.2.1).
- A profile page or menu.
