## Objective

Tests pin down the two pieces of model logic that are hardest to check by eye:
reporting-cycle detection and building the org tree.

## Background

- **`getCycles`** (in `operations.ts`) runs Tarjan's strongly-connected-
  components algorithm over the "reports to" graph built from supervisor
  references. It returns groups of member **indices** that report to each other
  in a loop. The only time it was ever tested was by hand (commit
  `f68b801`).
- **`buildOrganization`** (in `organization.ts`, from W38.1.2) turns the flat
  `members` array into sectors → departments → teams. The spreadsheet renders
  whatever it returns, so a mistake here shows up as a member in the wrong team
  or missing entirely.

## Files you will touch

- `utils/model/operations.test.ts` (add a `describe("getCycles")`)
- `utils/model/organization.test.ts` (new)

## What to change

**`getCycles`**, with fixtures where you control who supervises whom:
1. No supervisors at all → no cycles.
2. A simple chain A → B → C → no cycles.
3. A ↔ B → one group containing both.
4. Two separate loops → two groups.
5. Decide, and test, what a member who supervises **themselves** returns. Read
   the code to find out what it does now.
6. Only **current** positions should count. A supervisor on an ended position
   is history, not a reporting line. Check whether the code agrees.

**`buildOrganization`**:
1. Members land in the right sector → department → team from their current
   positions.
2. A member with current positions in two teams appears in both.
3. Ended positions do not place a member anywhere.
4. Empty input gives an empty (or empty-shaped) result without throwing.

## How to approach it

- Draw each `getCycles` fixture as a small arrow diagram in a comment above the
  test. It is the fastest way for a reviewer to check the expected answer.
- Index-based results depend on input order. Assert on the **set** of members
  in each group (map indices back to names and sort) so the tests do not break
  when someone reorders a fixture.
- As in W45.4.2: if behaviour looks wrong, log it and use `it.todo`. Do not fix
  it here.

## Acceptance criteria
