## Objective

A short written audit of the Crew Formations sheet's visual system, and that
system expressed as named Tailwind theme tokens the rest of the app can use.

## Background

The business spec says the product *"should have the same design and layout as
our current Crew Formations spreadsheet."* Today's colours are placeholders:
yellow sectors (`bg-yellow-300`), red departments (`bg-red-100`), purple team
headers (`bg-purple-100`). None of them were taken from the sheet.

What the sheet does, from a look at the Team Whale block (verify all of this
yourself, since this is a starting point, not the audit):

- A **full-width green title bar** with the team name in dark green, bold,
  centred.
- A **lavender stats row**: Availability, Median Proficiency, Max developers,
  Tech Stack, Website.
- A **role row** where the cell colour encodes the role: pale yellow for
  leads (PL), light blue for developers (A. Developer, Developer).
- A **row-label column** on the left (Role, Name, Email, Discord,
  Availability, Proficiency, GitHub). The app currently has no labels at all.
- **Thick black borders** separating the leads from the developers and one team
  from the next.
- A colour **KEY** somewhere in the sheet that explains the role colours.

Tokens come first, before restyling anything, so that 6.2, 6.3 and Kevin's
navbar badges (W45.2.2) all use names like `bg-formations-lead` rather than
three slightly different yellows.

## What to change

1. In the real Crew Formations sheet, find one example of every distinct block:
   sector header, department header, team title bar, stats row, each role
   colour, row labels, the KEY, and any status colours (BREAK, INACTIVE). Take a
   screenshot of each.
2. Record each colour's hex value. Take it from the sheet's fill-colour picker,
   not an eyedropper on a screenshot, because screenshots shift colours. Also
   record the font, weights, border widths and alignment.
3. Write `formations-design-audit.md`: a table of *element → colour/type/border →
   token name*, with your screenshots linked or embedded. Note anywhere the
   sheet is inconsistent with itself and which version you chose.
4. Add the tokens to `src/app.css` with Tailwind v4's `@theme`, named by
   **meaning**, not appearance: `--color-formations-lead`, not
   `--color-pale-yellow`.
5. Check contrast. Text on every fill must meet WCAG AA (4.5:1 for body text).
   Where the sheet's own colours fail, darken the text, not the fill, and note
   it in the audit.

## How to approach it

- Tailwind v4 has no `tailwind.config.js` theme by default. Tokens live in CSS
  under `@theme`. There is a leftover `tailwind.config.js` in the repo. Check
  whether it is still used and note it in the audit; do not delete it in this
  spec.
- Keep the token list small. About 10–15 tokens is right. If you have 30, some
  are the same colour.

## Acceptance criteria

- [ ] The audit doc covers every block type listed in step 1, with
      screenshots.
- [ ] Tokens exist in `app.css`, named by meaning, and `bg-formations-*`
      classes work in a component (try one, then revert it).
- [ ] Every text/fill pair is noted as passing AA, or adjusted.
- [ ] `npm run build` passes.
