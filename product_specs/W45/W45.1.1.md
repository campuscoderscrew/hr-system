## Objective

Write one function that takes a member the way it looks after a JSON round
trip and returns a real `Membership` again, with real `Date` objects.

## Background

This continues W43 "Move model ownership to the server". The last step of this
feature (W45.1.3) swaps `import { members } from data.ts` for
`fetch("/api/members")`. That swap has a trap most people only find at runtime.

**JSON has no date type.** `res.json(members)` turns every `startDate`,
`endDate`, `joinDate`, `createdAt` and `updatedAt` into an ISO string. TypeScript
still believes they are `Date`s, because `response.json()` returns `any`. The
first `.getTime()` call then crashes. `describeTenure` in `members.tsx` makes
exactly that call.

The fix is to convert the strings back right where the data enters the app, so
no other code ever sees a string date. Doing that as its own spec means W45.1.3
can stay a plain "change where the data comes from" change. Manan's W45.3.2
needs the same conversion in the other direction, so put it somewhere the server
can import too.

## Files you will touch

- `utils/model/serialization.ts` (new)

## What to change

1. Create `utils/model/serialization.ts` and export `reviveMember(raw: unknown):
   Membership`.
2. It converts every date field on the member (`joinDate`, `createdAt`,
   `updatedAt`) and every date field on each `positionHistory` entry
   (`startDate`, `endDate`). Optional fields stay `undefined` when they are
   missing. Do not turn a missing `endDate` into `Invalid Date`. A missing
   `endDate` is what marks a position as **current**, so getting this wrong makes
   every position look ended.
3. Export `reviveMembers(raw: unknown): Membership[]` too.
4. If a date string does not parse, throw an error that names the member and
   the field. Failing loudly here is far better than an `Invalid Date` showing up
   three components away.

## How to approach it

- Check your understanding first: in a scratch script, run
  `JSON.parse(JSON.stringify(members[0]))` and look at what `startDate` has
  become.
- `new Date(str)` returning an object does not mean the parse worked. An
  invalid date is still a `Date`. Look up how to detect one (hint:
  `getTime()`).
- Use the `Membership` and `Position` types to list the fields rather than
  guessing. If someone adds a date field later, this function is where it has to
  be added too. Leave a comment saying so.

## Acceptance criteria

- [ ] `reviveMembers(JSON.parse(JSON.stringify(members)))` yields members whose
      date fields are all `Date` instances (check a few with `instanceof`).
- [ ] Current positions (no `endDate`) are still current afterwards:
      `currentPositions()` returns the same count before and after.
- [ ] A malformed date throws an error naming the member and the field.
- [ ] The file imports nothing from `src/`, so the server can use it too.
- [ ] `npm run build` passes.

## Out of scope

- Calling it from the page (W45.1.3) or the server (W45.3.2).
- A general-purpose JSON reviver for every type in the model.
